# Practitioner supplements

Use this file only as a supplement to the Google Search Central framework. These workflows help discover demand, prioritize opportunities, and validate practical execution, but they do not replace Google Search Central guidance.

## Non-negotiable rule

Google Search Central remains the primary framework. Practitioner methods are optional tactical inputs. If a tactic conflicts with Google Search Central, reject or reframe it. If a tactic is uncertain, label it as experimental and validate it with Search Console, analytics, SERP observation, or user behavior.

## What this supplement is for

Use these workflows when the user asks for:

- demand discovery for indie products, content sites, or global websites
- keyword and topic mining beyond basic keyword tools
- competitor/source tracing and reverse engineering
- GSC-driven expansion of existing pages or new internal pages
- GEO/AI-search observation and measurement
- tool-assisted SEO execution using Semrush, Ahrefs, Similarweb, Google Trends, GSC, Bing, Discord, YouTube, browser extensions, or custom crawlers

## Demand discovery workflow

1. Start from real user need, not search volume alone.
2. Collect seed signals:
   - Google search syntax and advanced operators
   - Google Trends and related queries
   - GSC query data for existing sites
   - competitor landing pages and traffic sources
   - product directories, AI navigation sites, income/ranking lists, communities, Discord, plugin reviews, complaint threads
   - outbound traffic and backlink patterns
3. Expand by roots, variants, misspellings, adjacent user groups, and pain-point language.
4. Score each idea:
   - user pain intensity
   - search intent clarity
   - competition level
   - content/product fit
   - monetization path
   - ability to add original value
   - risk of being thin, duplicated, doorway-like, or overly keyword-driven
5. Validate with a small page, tool, landing page, or manual outreach before scaling.

## Competitor and source tracing

Use competitor research to understand markets, not to copy.

Recommended questions:

- Which pages receive meaningful traffic?
- What queries or intents likely drive those pages?
- What page types, templates, and internal links are used?
- What user problem is the competitor solving?
- What is missing, outdated, weak, or overly generic?
- Can the user create something more useful, original, interactive, accurate, localized, or easier to use?

Risk controls:

- Do not copy page structures blindly.
- Do not create many near-duplicate pages from competitor keywords.
- Do not treat DR, KD, search volume, or Similarweb estimates as facts; treat them as directional signals.

## GSC-driven expansion

Use this when the user already has impressions or long-tail queries in Search Console.

1. Export queries by page.
2. Group queries into:
   - matching existing intent: improve the current page
   - adjacent subtopic: add a section or FAQ if genuinely useful
   - distinct intent: consider a new page
   - irrelevant query: clarify page focus and reduce ambiguity
3. For new pages, require a unique angle or substantial value beyond keyword matching.
4. Validate after publishing with impressions, clicks, average position, CTR, indexing status, and user engagement.

## GEO and AI-search observation

Treat GEO as SEO plus measurement and content clarity.

Useful tactical observations:

- Track referral patterns from AI assistants where analytics exposes them.
- Compare branded and non-branded mentions across AI surfaces manually when tools are unreliable.
- Identify pages that already answer concise questions well and strengthen evidence, structure, and freshness.
- Build content with clear sections, direct answers, examples, sources, and original experience.

Do not claim guaranteed AI Overview, AI Mode, or chatbot citations.

## Tool-assisted workflows

Use tools as inputs, not authorities.

- Google Search Console: query/page diagnostics, indexing, CTR, traffic drops, enhancement reports.
- Google Trends: demand direction, seasonality, emerging terms, country comparison.
- Semrush/Ahrefs/Similarweb: competitor discovery, rough traffic/channel estimates, keyword candidates, backlinks.
- Bing keyword data: supplemental keyword discovery, especially when Google data is sparse.
- Crawlers and SEO scanners: metadata, headings, links, status codes, canonicals, sitemap, robots, structured data, and duplicate checks.
- YouTube/community/Discord/plugin reviews: pain-point language and product/content ideas.

Always state that third-party metrics are estimates unless sourced from the user's own analytics or Search Console.

## Output template: practitioner tactic review

When evaluating a third-party SEO tactic, answer:

1. What is the tactic trying to achieve?
2. Which Google Search Central principle does it align with?
3. Where can it conflict with Google Search Central?
4. What is the safest version of the tactic?
5. What should be measured before scaling?
6. Should this become a repeatable workflow, one-off experiment, or rejected tactic?
